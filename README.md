# ناب — نظم آفرینان بیدار

سامانه مدیریت گشت نگهبانی با پنل فارسی، بک‌اند Java و اپ اندروید با رویکرد آفلاین. نام انگلیسی و شناسه پروژه: **Nab**.

## وضعیت فعلی

پنل و API پیاده‌سازی و در محیط محلی آزمایش شده‌اند. کد اپ اندروید، ذخیره‌سازی آفلاین و سینک نوشته شده و تست‌های منطق آن اجرا شده‌اند. ساخت APK و آزمایش روی گوشی واقعی هنوز معیار تحویل نهایی است؛ بدون نتیجه موفق ساخت، فایل نصب آماده فرض نشود. iOS فعلاً متوقف است؛ اسکلت موجود آن صرفاً نگهداری می‌شود. استقرار اینترنتی هم فعلاً در محدوده کار نیست.

## قابلیت‌ها

- نقش‌های مدیر، سرپرست و نگهبان؛ ایجاد کاربر و فعال/غیرفعال‌کردن حساب.
- تعریف محل، چک‌پوینت، QR قابل چاپ، مسیر مرتب و مأموریت زمان‌دار.
- شروع و پایان مشخص مسیر؛ رد اسکن خارج از ترتیب و پایان ناقص در اپ آفلاین و سرور؛ پشتیبانی از مسیر حلقه‌ای.
- توقف گشت ناقص با علت و وضعیت ناموفق، جدا از پایان موفق.
- چرخه قابل تنظیم کار/استراحت، از جمله ۲۴/۲۴؛ تولید نوبت‌ها با فاصله زمانی یا ساعت‌های ثابت هفتگی و روزهای انتخابی.
- پیش‌نمایش روزانه شیفت، استراحت و گشت؛ ساخت کل هفته با یک ثبت؛ استفاده مجدد از الگو در هفته بعد با حفظ چرخه و جلوگیری از تکرار همان بازه.
- اجرای گشت‌های از قبل دریافت‌شده بدون اینترنت؛ بازیابی صف و گشت فعال بعد از بسته‌شدن اپ.
- ثبت حادثه، اهمیت و عکس؛ GPS با وضعیت موجود/ناموجود/قدیمی/کم‌دقت، بدون مسدودکردن گشت به‌علت موقعیت نامناسب.
- سینک دستی، پایان گشت، بازگشت اتصال، بازگشت به اپ و تلاش دوره‌ای هنگام بازبودن اپ؛ درخواست سینک پس‌زمینه با زمان‌بندی تحت کنترل سیستم‌عامل.
- نقشه آخرین موقعیت‌های دریافت‌شده، رویدادها، تصاویر، پیشرفت نقاط، تأخیر شروع و مدت گشت.
- گزارش ترکیبی بر اساس نگهبان، محل، مسیر، نوبت، وضعیت، ماه شمسی یا بازه دلخواه؛ PDF فارسی و Excel واقعی با جزئیات اختیاری.
- کنترل نقش، رمز BCrypt، توکن‌های قابل ابطال، تأیید دریافت رویداد/عکس، ثبت عملیات مدیریتی و تصاویر خصوصی.

فعلاً **فقط QR** پیاده شده است؛ NFC، RFID، Push، SOS، چندسازمانی و ویرایش/حذف جامع هنوز جزو قابلیت‌های آماده نیستند. گشت آفلاین پس از سینک در پنل دیده می‌شود؛ «دریافت‌نشده» اثبات انجام‌نشدن نیست.

## ادامه کار در رایانه دیگر

```powershell
git clone https://github.com/AliMirzad/Nab.git
cd Nab
```

پیش‌نیازها: Java 21، Maven 3.9+، Node.js 24 و Flutter 3.47.7 / Dart 3.13.5 مطابق lockfile. برای APK، Android Studio و Android SDK نیز لازم‌اند. ابزارها باید در PATH باشند؛ مسیر مخصوص رایانه سازنده در کد لازم نیست.

### ۱. سرور محلی

از ریشه پروژه:

```powershell
.\scripts\run-api.ps1 -Demo
```

یا داخل `backend`:

```powershell
$env:DEMO_MODE='true'
mvn spring-boot:run
```

API: `http://localhost:8080/api/health`. داده دمو تنها در دیتابیس خالی ساخته می‌شود.

### ۲. پنل، در ترمینال دیگر

```powershell
cd web
npm ci
npm run dev
```

پنل: `http://localhost:5173`.

| حساب صرفاً آزمایشی | نام کاربری | رمز |
| --- | --- | --- |
| مدیر | `admin` | `Admin@12345` |
| نگهبان | `guard` | `Guard@12345` |

این رمزها فقط برای دمو هستند. دیتابیس دمو را روی اینترنت منتشر نکنید. تولید واقعی با `DEMO_MODE=false`، دیتابیس مجزا و `ADMIN_PASSWORD` قوی آغاز می‌شود. خاموش‌کردن حالت دمو، حساب‌های قبلاً ساخته‌شده را حذف نمی‌کند.

### ۳. اندروید

```powershell
cd mobile
flutter pub get
flutter doctor -v
flutter run --dart-define=API_URL=http://10.0.2.2:8080
```

`10.0.2.2` مخصوص شبیه‌ساز Android است؛ برای گوشی واقعی از IP شبکه محلی رایانه استفاده کنید. آدرس سرور در صفحه ورود اپ هم قابل تنظیم است؛ پس از اتصال اولیه، دستگاه برای جلوگیری از آمیختن صف‌ها به همان سرور مقید می‌شود.

```powershell
flutter build apk --debug --dart-define=API_URL=http://10.0.2.2:8080
```

خروجی مورد انتظار: `mobile/build/app/outputs/flutter-apk/app-debug.apk`. برای نسخه release، کلید متعلق به مالک محصول را طبق `android/key.properties.example` تنظیم کنید؛ کلید و رمز امضا هرگز وارد Git نشوند. release باید به API دارای HTTPS متصل شود.

## آزمون‌ها

```powershell
# سرور را پیش از verify متوقف کنید؛ JAR باز در Windows ممکن است قفل باشد.
cd backend
mvn clean verify
cd ../web
npm ci
npm test
npm run build
cd ../mobile
flutter pub get
flutter analyze
flutter test
```

آزمون واقعی اپ/سرور فقط با سرور محلیِ دمو و عمداً به‌صورت انتخابی اجرا می‌شود:

```powershell
flutter test test/api_contract_test.dart --dart-define=NAB_INTEGRATION_URL=http://localhost:8080
```

این آزمون نوبت و رخداد آزمایشی ایجاد می‌کند؛ آن را به دیتابیس مشتری متصل نکنید. گردش کار بررسی، تست سرور روی PostgreSQL، تست وب و تحلیل/تست Flutter را اجرا می‌کند. گردش کار Android، ساخت debug APK را بررسی و در صورت موفقیت به‌عنوان artifact ذخیره می‌کند؛ وجود فایل workflow به‌تنهایی به معنی ساخت موفق نیست.

## ساختار و مستندات

- `backend/`: Spring Boot، JDBC، Flyway، H2 محلی و PostgreSQL برای استقرار.
- `web/`: React، TypeScript، Vite، رابط فارسی راست‌به‌چپ.
- `mobile/`: Flutter؛ تمرکز فعلی روی Android، SQLite و صف ارسال پایدار.

- [نتیجه بازبینی کد و ریسک‌های باقی‌مانده](docs/REVIEW.md)

## استقرار آینده

فایل‌های Docker و Compose آماده‌اند، اما اجرای production باید جداگانه تأیید شود:

```powershell
Copy-Item .env.example .env
# DB_PASSWORD و ADMIN_PASSWORD را تنظیم کنید؛ رمز مدیر ۱۲ کاراکتر یا بیشتر، حداکثر ۷۲ بایت UTF-8.
docker compose up --build -d
```

پنل و API پشت پراکسی در `http://localhost:8088` هستند؛ HTTPS، دامنه، سیاست دسترسی و پشتیبان‌گیری قبل از انتشار عمومی لازم‌اند. حجم‌های دیتابیس و تصاویر باید با هم پشتیبان‌گیری شوند. یک نصب، یک سازمان را پوشش می‌دهد.
